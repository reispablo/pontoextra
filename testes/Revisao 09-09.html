Tipos de teste

Funcional ou não funcional?

Teste funcional

Verifica o que o sistema faz e se uma regra de negócio foi atendida.

O usuário consegue entrar com credenciais válidas?

Teste não funcional

Verifica como o sistema funciona em características de qualidade.

A tela de login responde rapidamente e é acessível?

Funcional: comportamento e regra. Não funcional: desempenho, segurança, usabilidade, acessibilidade e confiabilidade.

Técnica • caixa-preta

Entradas e saídas, sem olhar o código.

No cadastro
  • informar dados válidos;
  • deixar um campo obrigatório vazio;
  • usar um e-mail já cadastrado;
  • observar mensagem e tela final.
No login
  • usar credenciais válidas;
  • informar senha incorreta;
  • enviar campos vazios;
  • observar acesso ou mensagem de erro.

O testador conhece o comportamento esperado, fornece entradas e compara a saída observada com a esperada.

Introdução ao Cypress

O navegador executa o teste para nós.

Cypress é uma ferramenta de automação para aplicações web. Em um teste E2E, ele simula a jornada do usuário pela interface.

1

Abrir

Acessar a página que será testada.

2

Interagir

Localizar elementos, digitar e clicar.

3

Verificar

Comparar o resultado com o esperado.

npx cypress open   // abre o Cypress no modo interativo
npx cypress run    // executa os testes pelo terminal
Estrutura e comandos básicos

Preparar → agir → verificar.

describe('Funcionalidade', () => {
  beforeEach(() => {
    cy.visit('/pagina-conhecida')
  })

  it('descreve o comportamento esperado', () => {
    // preparação dos dados
    // ação principal
    // asserções do resultado
  })
})

cy.visit()abre uma página

cy.get()usa seletor CSS

cy.contains()busca texto visível

.type()digita em campo

.click()executa clique

.should()verifica resultado

Seletores e asserções

Encontre bem. Comprove melhor.

Seletores claros

cy.get('#email')
cy.contains('button', 'Entrar')

Prefira IDs estáveis, atributos e textos significativos.

Estado observável

.should('be.visible')
.should('have.value', valor)
.should('contain', mensagem)
.should('not.exist')

Mensagem e interface final formam um oráculo mais forte.

Evite cy.wait(3000) como estratégia principal. O Cypress já repete consultas e asserções até o limite configurado.

Cypress • cadastro

Preencher, enviar e comprovar.

it('cadastra um usuário com dados válidos', () => {
  const email = `revisao.${Date.now()}@email.com`

  cy.visit('/cadastro')
  cy.get('#nome').type('Aluno Revisão')
  cy.get('#email').type(email)
  cy.get('#senha').type('Senha123')
  cy.get('input[type="submit"]').click()

  cy.get('.alert-success')
    .should('contain', 'Usuário inserido com sucesso')
  cy.contains('button', 'Entrar').should('be.visible')
})

O e-mail muda a cada execução para não colidir com um cadastro anterior.

Clínica de código

Encontre três fragilidades.

it('faz cadastro', () => {
  cy.visit('/cadastro')
  cy.get('#email').type('aluno@email.com')
  cy.wait(3000)
  cy.get('input[type="submit"]').click()
})
O e-mail fixo pode colidir com um cadastro anterior; a espera fixa deixa o teste lento e instável; e não existe nenhuma asserção que comprove mensagem ou estado final. Além disso, o exemplo não mostra o preenchimento dos demais campos obrigatórios.
Cypress • login

Usar credenciais e confirmar o acesso.

it('entra com e-mail e senha válidos', () => {
  cy.visit('/login')
  cy.get('#email').type(usuario.email)
  cy.get('#senha').type(usuario.senha)
  cy.contains('button', 'Entrar').click()

  cy.get('.alert-success').should('be.visible')
  cy.contains('a', 'Sair').should('be.visible')
})
Entrada

E-mail e senha de um usuário cadastrado.

Saída esperada

Mensagem de sucesso e área autenticada visível.
